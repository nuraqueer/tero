# Sefirah private message engine

Official OpenMLS 0.9.1, RustCrypto provider, and our own UniFFI object interface.
This is a native encryption and encrypted-state foundation with a development-only
Android and iOS Expo bridges, **not working app chat**.
Expo Go cannot load it. Native iOS verification and message delivery remain pending.

`PrivateChat` owns one two-member MLS group. Construct it with the unlocked
account's existing 32-byte Ed25519 secret and the expected contact's did:key.
The joining party calls `key_package()`, the initiating party calls
`initiate(package)`, and the joining party calls `join(welcome)`.
Both can then `encrypt(text)` and `decrypt(wire)`. Rust `shutdown()` drops the provider
and permanently closes that object. Never print or serialize the object or seed.
Only the public KeyPackage, Welcome and encrypted application bytes cross the
interface. Each session supports one handshake; a rejected Welcome may consume
the init key, so discard that engine rather than retrying indefinitely.

The expected peer must come from accepted-contact state. The Rust engine checks
identity/key bindings, not registry admission or account permissions. MLS wire
bytes expose protocol metadata such as group identifiers; the future carrier
envelope and privacy route must still hide them appropriately.

## Integration still required

Kotlin UniFFI bindings are generated by `build-bindings-android.sh`. The Android
Expo module is enabled only in `SEFIRAH_NATIVE_BUILD=1` builds and has a disabled
stub otherwise. A session-owned JS adapter closes engines on lock, decoy entry,
account replacement and unmount. Its native handles are capped at 16 per module.
UniFFI uses JNA 5.18.1 on Android; there is no third-party chat SDK. Rust uses
`shutdown()` because UniFFI reserves `close()` for Kotlin object disposal.

`PrivateChat::new` is ephemeral for synthetic tests. `PrivateChat::open` accepts
a separate storage key and native path, and restores the current authenticated
OpenMLS state. Android chooses a private no-backup path from an opaque namespace.
The JS session derives its storage key with existing `deriveSecret(seed, 'app', 5)`.
The manager owns a copy and clears it on close. No plaintext snapshot crosses JS.

Each successful mutation commits state before returning. Encryption also commits
its exact ciphertext to a pending queue; decryption commits plaintext to an
encrypted inbox. `pending()` and `received()` recover those records. Queue IDs
are hashes of wire bytes, not delivery/read receipts. SQLite serializes writers
and rejects stale revisions. Persistence failure closes the native engine; close
its JS handle before reopening. There is no older-snapshot recovery fallback.
Limits are 32 pending records, 32 inbox records and 4 MiB serialized state.
`handshakeState()` derives fresh, offered or established state from the saved
engine. `acknowledgePending(id)` atomically removes only that exact wire ID after
the caller verifies its acknowledgement; duplicate/unknown IDs return false.
Malformed IDs are rejected. A KeyPackage cannot be consumed before joining its
Welcome, preserving its retry bytes across restarts. Failed or stale writes
retain the committed queue and close the failed writer. This API is local queue
consumption, not proof of delivery or reading, and never deletes inbox content.
The bridge advertises `queueVersion: 1`; older installed binaries cannot silently
substitute for these methods. No persisted schema changes were needed.
Expiry, authenticated receipts and inbox capacity management remain required
before real member messages are enabled.

The diagnostic uses random test storage keys and separate cache files, reopens
engines during the handshake and exchange, and removes only those probe files.
There is also a two-process native probe:

```sh
ANDROID_HOME=/path/to/android-sdk bash build-android.sh --example state_probe
# Run the built executable with a disposable directory and prepare, then verify.
```

SQLite uses authenticated encrypted records, synchronous FULL and secure_delete.
Historical encrypted pages may survive journals, flash or copied backups. This
is not forensic erasure or malicious rollback protection. Keep state out of
backups; do not recover it by restoring an older database. A schema and OpenMLS
version check rejects unsupported saved state. Crash/power-loss injection and
background-thread performance still need device work before real chats.

The base iOS bridge compiled in TestFlight build 8. New queue methods require an
updated native build and device probe before use.
There is no key update API yet, so this slice does not establish
post-compromise healing. It also has no handshake distribution, transport,
receipts, retention enforcement or message UI. Group changes are rejected.
No complete memory erasure guarantee is made for OpenMLS provider allocations.

The product retention rule is seven days for unread messages, or 24 hours after
both participants read a message. This must be enforced by later message storage
and authenticated receipts, not by deleting MLS ratchet state on a timer.

See [the engine specification](../../../../docs/specs/_root/0001-sefirah/0007-private-message-engine.md)
and [message state specification](../../../../docs/specs/_root/0001-sefirah/0008-message-state.md).

## iOS and TestFlight

On macOS with Xcode and Rust installed, run `bash build-ios.sh` before CocoaPods.
It generates Swift bindings from the host library metadata and builds the locked
Rust source as an arm64 iOS static archive. Generated outputs remain ignored.
Outputs live inside `ios/Generated`, within the CocoaPods specification's root,
so its source glob includes the generated Swift binding as well as the bridge.
This archive supports physical devices, not simulators. The pod exposes an
unavailable stub unless `SEFIRAH_NATIVE_BUILD=1` is set.

The app's EAS preinstall hook installs Rust on the disposable macOS build worker
if needed, then runs this script before CocoaPods. The `testflight` profile uses
store distribution, includes the native module and test diagnostics, disables OTA
updates, and targets the preserved local registry at `http://192.168.1.4:8794`.
Keep the Android USB API forwarding available. Recheck the address before building.

The Swift module keeps the original synchronous diagnostic interface and adds
asynchronous storage and delivery calls with the same 16 engine limit as Android. iOS state uses Application Support, complete file protection and a
backup excluded directory. Synthetic probes use a separate cache directory;
their cleanup cannot remove account state. Swift copies and Rust allocations
still prevent any claim of complete memory erasure. Disk and delivery calls now run through asynchronous native operations. Unique
owner registration prevents queued opens after blur or lock; late JS outputs are
rejected. The original synchronous calls remain for the explicitly invoked probes.

From `apps/app`, the store build command is:

```sh
export PATH="$HOME/.bun/bin:$HOME/.cache/codex-runtimes/codex-primary-runtime/dependencies/node/bin:$PATH"
bunx eas-cli build --platform ios --profile testflight
```

On this host, include the existing Node directory as shown. With Node missing
from PATH, bunx ran EAS under Bun and both metadata and archive uploads timed out.
The same EAS uploader accepted a synthetic metadata upload under Node in 1.8
seconds; the full project archive then uploaded in 13 seconds. Bun remains the

## Foreground chat delivery implementation

`deliveryVersion: 1` adds native message records and MLS authenticated delivery,
read and ready controls. Snapshot version 2 preserves the existing group and
ratchet state while adding delivery records; unsupported old readers fail closed.
The retry queue remains 32 records, with at most 16 unacknowledged outgoing
messages to reserve room for controls. The separate delivery history holds at
most 256 messages inside the existing 4 MiB encrypted state bound. Expiry is
seven days unread or 24 hours after both read timestamps. Expired records are
removed on native operations, without claiming scheduled deletion while stopped
or forensic erasure. Read controls come from screen visibility in the chat UI.

TestFlight build 12 verifies native compilation of these APIs on iOS. New phone
behavior and protocol tests are deferred under the owner's current instruction.
The older synthetic diagnostic PASS does not prove this new delivery flow.
