# Tero design docs

Tero is a global, invite-only platform where queer people help each other:
community, verified professionals, health and HRT, travel and surgery
planning, legal help and wills, jobs, skills, housing and mutual aid.

These documents record the product direction and decisions as development proceeds. They include future features as well as implemented ones. D51 through D69 record the founder's Sefirah clarifications and delegated architecture recommendation on 12 October 2026; earlier central network assumptions must be read in that light. Later clarifications supersede earlier entries where explicitly stated.

## Decisions log

| # | Decision |
|---|---|
| D1 | Name is **Tero**, inspired by the Tarot Club in *Lord of the Mysteries*. |
| D2 | Global and borderless. Not hosted in, or operated from, hostile countries. |
| D3 | Run by a Pherus subsidiary in a safe country. Pherus is the parent. |
| D4 | One domain only: `tero.pherus.org`. No subdomains. |
| D5 | One Expo codebase for web, iOS and Android. Admin is behind sign-in on the same domain. |
| D6 | ~~Sign-in through PassID.~~ Replaced by D24. |
| D7 | Sensitive data is encrypted on the device. Cloudflare stores only ciphertext (encrypted relay). |
| D8 | Joining is invite-and-vouch only, with single-use Tero cards. |
| D9 | Money is stablecoins only, non-custodial. Tero never holds funds. |
| D10 | Languages: English, Swahili, Chinese (zh) and French from day one. |
| D11 | Admins (council), moderators, professionals and members are separate roles. |
| D12 | Professional verification is per country and per profession. AI assists, and the council votes. |
| D13 | Wallet chain: **Celo**, with USDT and USDC. Fees paid in the stablecoin itself. Other EVM chains can be added later with the same code. |
| D14 | Council: the Fool can add a council member alone. Other council members can only add someone by vote. The Fool can veto any vote. |
| D15 | Code license: **AGPL-3.0** (in `LICENSE`), with a contributor agreement (`CLA.md`) so Pherus can ship to the app stores. |
| D16 | Minimum age: **18, or the country's legal age if higher**. |
| D17 | App store rules and app size are design constraints from day one. |
| D18 | ~~PassID registration.~~ Not needed after D24. `tero.pherus.org` is still in development. |
| D19 | The app locks when it's closed, or after 30 minutes in the background (changed 2026-10-06 at the founder's request; it used to lock on every switch away). A decoy passcode on the same screen opens only basic info and silently sends a duress alert. No disguised icon. |
| D20 | Private chats clear by default and are kept only if both agree. Screenshot alerts warn but don't block. |
| D21 | Spaces (live audio rooms) and anonymous "someone to talk to" are part of Support and care. |
| D22 | The council oversees moderators and countries. Moderators moderate the platform. The Fool can remove a council member alone; otherwise it takes a vote. |
| D23 | Tor is built into the iOS app when added. |
| D24 | **No PassID.** Each person's account is a set of keys they hold, like a crypto wallet. One seed, separate unlinkable keys for identity, messaging, wallet and other apps. |
| D25 | Duress alerts go to whoever brought the person in and the country's council. Recovery uses a one-time passcode from that same person or group, after a waiting period. |
| D26 | Voice: end-to-end encrypted Spaces with up to 6 speakers and unlimited listeners, private voice calls with professionals, and voice disguise. |
| D27 | Recovery phrase is **12 words** (plus social recovery). |
| D28 | ~~Discord-style communities.~~ Replaced by D34. |
| D29 | Recovery: pick your own card and the bond card from a shuffled deck, confirmation outside the app, then a 24-hour wait. |
| D30 | Strict protections are on by default only in high-risk countries or regions (including some US states), set by the country pack. Anyone can turn them on. |
| D31 | Danger signals in Spaces: a secret danger reaction and a personal safe word. Trusted people in the room are told, the person is dropped, and the app slowly switches to basic mode. |
| D32 | Live subtitles with translation in Spaces, done on phones so they stay end-to-end encrypted. |
| D33 | ~~Discord structure with Apple look.~~ Replaced by D34. |
| D34 | **Tero's own design**, made the way Apple designs in 2026 (Liquid Glass, content first). Five tabs: Gathering, Circles, Messages, Help (was Suits, see D41), You. Circles are one conversation with topics and live Spaces. |
| D35 | Colours: warm ivory, slate text, clay accent. Fonts: Newsreader (serif headings) and Instrument Sans. Calm and grown-up, not playful. |
| D36 | **Tero partners.** Clinics, pharmacies and lawyers can become verified Tero partners. Members show their Tero card (three words that change every 30 seconds) and partners show the same words back. Places that don't know Tero are marked "Not aware of Tero": members are told not to show their card there, and the listing shows what members found (availability, price ranges). |
| D37 | Posting has types: Post, Ask for help, Offer help, Event, Fundraiser and Poll, each with its own fields. Photos are blurred and stripped of location before upload. |
| D38 | The "Tero" word is set in JetBrains Mono beside a small tarot-card mark. Final logo to be picked from the logo concepts. |
| D39 | **Chats use OpenMLS** (the MLS standard) for 1-to-1, groups, Circles and Spaces: the official crate with our own thin binding, no third-party wrappers. See [messaging-choice.md](messaging-choice.md). Built after the other work. |
| D40 | **The web is for the Fool and the council**, plus the public site. Members and moderators use the phone app. The Fool sets up on the web and seats council members with council cards (they join at Sequence 1, each with a card no other council member holds). |
| D41 | **No tarot suits for help.** Cups, Pentacles, Swords and Wands are gone (founder, 2026-10-06). The tab is **Help**, with four plain areas: Support and care, Work and money, Safety and law, Health and growth. Tarot stays only for member cards and Sequences. Parts are built as real features, one by one, instead of placeholders. |
| D42 | **The directory is real** (first feature built after D41). Members add places to the seven directory parts (mental health, safe spaces, legal, travel, providers, affirming care, general health): name, country, city, what they offer, contact, cost, "sees people from abroad" and "not aware of Tero". Members vouch once per place ("I've been, it went well"), never for their own. The author, the Fool or the council can remove a place. Who added or vouched is stored only as a keyed pseudonym (HMAC with `AUTH_SECRET`), never the member's key; rotating `AUTH_SECRET` forgets which places are "yours". Ten new places per member per day. "Tero partner" (verified) is set by the council only, later. |
| D43 | **Mutual aid is real.** Members post a request or an offer (rent and housing, food, travel, health and medicine, work, other) with a title, details, country and city; posts show no name. Replies are short notes seen only by the person who posted, one per member per post; until private chats exist, the note is how two people reach each other, and the form warns not to share more than needed. The author marks a post done; posts and their replies are deleted after 30 days. Three posts per member per day. The author, the Fool or the council can remove a post. |
| D44 | **Jobs are real.** Members share openings (job, freelance, internship, mentoring) with a role, optional organisation, details, remote or a country and city, optional pay, and how to apply. Openings show no name, come down after 60 days, five per member per day; the poster, the Fool or the council can remove one. Search and filters (remote only, kind of work) run on the phone. |
| D45 | **Stories are real.** Members share firsthand experiences under a topic (coming out, transition, health, family, work, moving somewhere safer, other), with an optional content note that keeps the story folded until the reader opens it, and an optional country. Stories show no name and only the month they were shared; the form asks people to leave out identifying details. Members can say "thank you for sharing" once per story, never on their own. Two stories per member per day; the teller, the Fool or the council can remove one. Stories don't expire. |
| D46 | **Skills and learning are real.** Members post "I can teach", "I want to learn" or a resource (a free course or workshop, which needs an http(s) link), under a topic (tech, design and art, languages, business and money, trades and crafts, wellbeing, other), online or in a country. Replies to teach and learn posts go only to the poster, as with mutual aid; resources take no replies. Three posts per member per day; the poster, the Fool or the council can remove one. The open guides stay linked at the top. |
| D47 | **Journeys are real and private.** A member's plans (from a template: start gender-affirming care, change name or gender marker, move somewhere safer, plan a surgery; or their own) are sealed on the phone with a key from the 12 words (XChaCha20-Poly1305, padded to 1 KiB). The server keeps one sealed box per member under a pseudonym and can't read it; versions stop two devices overwriting each other. Restoring with the 12 words brings them back. |
| D48 | **Face ID / fingerprint unlock, opt in, phones only** (founder, 2026-10-06). Turned on with one switch in You (no Tero passcode; the phone confirms the owner). The seed is kept in the Keychain/Keystore on this device only while the phone has a passcode; unlocking asks the phone to confirm the owner (Face ID or fingerprint, with the phone's own passcode as the usual fallback) and skips the slow passcode stretching. Changed 2026-10-06: offered once after a passcode unlock (phone alert, one tap), also a switch with a clear on/off status in You; the lock screen leads with the biometric and "Use passcode" falls back to Tero's own passcode, not the phone's. Face ID on iPhone does not work inside Expo Go (Expo limitation), so the preview says so; it needs a development build or TestFlight. Android works in Expo Go. It always opens the full Tero (never the decoy view), and the settings screen warns that someone can force a face or finger. It turns itself off when the phone's passcode is removed, and when a vault is set up or restored. Not on the web. |
| D49 | **Help is cards, with one place to create** (founder, 2026-10-06). One "Share or ask" button opens every way to post (ask for help, offer help, suggest a place, share a job, share a story, teach or learn, start a journey) and goes straight to that form. Every part is a card (crisis and map first), and the seven place directories are one row of chips under "Places members trust". The four areas are no longer shown in the app. |
| D50 | **Tero is a queer resource platform, not a game** (founder, 2026-10-06). Line: "Queer knowledge, resources, community, & support": a global, community-driven knowledge and resource platform by Pherus for the LGBTQIA+ community, queer to queer, kept trustworthy by community submission and moderation. The tarot club is an idea behind it, not a theme to show off. The public site is plain and light (one ground, dark text, the warm accent only for links; no dark bands, no gold cards, no novel quotes). **The Fool is not advertised**: no Fool card on the public site or in the web console, no card name in the console greeting. Languages are a dropdown on the web and a list on phones, so more can be added. |
| D51 | **Sefirah is the network beneath Tero** (founder, 2026-10-12). Q2Q means a participant network combining Tor, peer communication, torrent inspired distribution, and hybrid Durable Object transport. Durable Objects provide transport, coordination, and limited statistics, rather than central ownership of membership and application data. The public domain must not be a required single point of access. This replaces the earlier central network assumption in D4, D5, D7, and the architecture document; it does not remove the public website, Expo application, or administration. The network is not yet implemented. |
| D52 | **No member IP exposure to peers** (founder, 2026-10-12). Transport selection must preserve this requirement and must not silently downgrade to a direct connection that exposes a member's IP address. Exact transport choices and failure behavior require design and verification. |
| D53 | **Participation in forwarding and storage is optional for ordinary members** (founder, 2026-10-12). Members opt in to helping carry other people's encrypted data; community operated nodes support availability. Quotas, retention, and participation controls remain to be designed. |
| D54 | **Full governance visibility for the Fool and council** (founder, 2026-10-12). Authorised administrators may inspect the full member roster and invitation relationships, but not private conversations. Those governance records must be encrypted for authorised readers; transport nodes must not gain the same visibility by carrying or storing the data. The roles, tarot identities, Spaces, resources, and administration experience remain. |
| D55 | **Sefirah first; Cloudflare and nearby exchange are fallbacks** (founder, 2026-10-12). Sefirah's own privacy preserving network is the default worldwide route. It must operate without Cloudflare when participating nodes remain reachable. Cloudflare is optional fallback transport. Nearby, AirDrop-like exchange is a local fallback without internet, with later synchronization; weak connections require queued and resumable delivery. Local exchange need not wait for a Cloudflare attempt. No fallback may silently relax D52. These transports and synchronization are not yet implemented. |
| D56 | **Recommend private verifiable records rather than a blockchain** (recommendation delegated by founder, 2026-10-12). Borrow signatures, integrity verification, and auditable records for membership and governance, keeping sensitive records encrypted for their authorised readers. Do not put the member roster or invitation graph on a public ledger. The donation wallet remains separate. Authority, voting, conflict handling, and revocation still require a concrete protocol; signatures alone do not solve those questions. |
| D57 | **Encrypted fallback storage bridges non-overlapping online sessions** (founder, 2026-10-12). A participant can publish while others are offline, disconnect after durable fallback acknowledgement, and another participant can retrieve the encrypted post later. Online participants exchange missing data through Sefirah without requiring Cloudflare. Retention and replica rules must preserve offline delivery; a first download alone is not grounds to delete the fallback copy. Minimise Cloudflare usage and target its free allowances with quotas and graceful capacity limits; unlimited free service is not guaranteed. |
| D58 | **Sefirah-first encrypted calls and Spaces** (founder, 2026-10-12). Private audio calls and live Spaces use eligible Sefirah media routes first, Cloudflare as fallback, with end-to-end encrypted media. This replaces the Cloudflare-only routing assumption in the earlier voice proposal without removing D26's product features. Media transport, privacy validation, and fallback capacity budgets are not implemented. |
| D59 | **Sefirah serves more than Tero** (founder, 2026-10-12). Other queer organisations can use the network and operate compatible nodes, supporting continuity beyond one application or operator. Shared transport does not confer shared governance or access to private data. Organisation isolation and interoperability remain to be built; continued operation depends on reachable nodes and surviving data copies. |
| D60 | **Unique usernames alongside tarot identities; lifetime-exclusive leadership cards** (founder, 2026-10-12). Every member has a unique username as well as a tarot identity. The Fool and council cards can never be issued to another person once assigned, regardless of whether the original holder remains active or retains their role. Account identity, username, tarot assignment, and permissions are separate concepts. Permanent issuance records, username conflict handling, and the ordinary versus reserved deck require implementation and further specification. |
| D61 | **Private calls: up to four participants; Spaces: six speakers plus listeners** (founder, 2026-10-12). Private audio calls are normally one-to-one, with a maximum of four participants in group calls. Spaces permit at most six simultaneous speakers including the host, plus additional listeners. The limits apply on primary and fallback routes. The founder requested comparison of fallback media options; Cloudflare Realtime is not yet selected. |
| D62 | **Free capacity is the initial operating constraint; masked addresses require real routing privacy** (founder, 2026-10-12). Do not require paid self-hosted servers or assume future spending to make the initial design work. Use participant resources, voluntary existing community capacity, and bounded free service allowances, with explicit behavior at capacity. Future spending may be considered separately. Masked addressing is acceptable, but bare member IPs must not be exposed to peers; an alias or hash alone does not satisfy that condition. No media transport has yet been selected or validated against these constraints. |
| D63 | **Tero handles, referral trees, and emergency governing authority** (founder, 2026-10-12). Handles are unique within Tero; `@thefool` is exclusive to the Fool. Ordinary invitations retain parent references for accountability and emergency escalation. Council members have independent referral branches, with the Fool's appointment recorded separately. The Fool can revoke council authority; council revocation otherwise requires a vote subject to the Fool's veto. Council appoints moderators; moderators and members can invite members. During the Fool's explicit compromise or decoy alert, a council member temporarily holds Sequence 0 while retaining their own identity and referral branch, and council members are notified. The Fool's restoration waits 24 hours, after which the acting council member returns to Sequence 1; council return also requires a 24-hour wait. Successor selection and safe restoration rules remain unresolved. This updates D25/D29's recovery model and D60's separation of permanent identity from current powers; it does not establish that revoked exclusive cards may be reissued. |
| D64 | **Role-specific compromise response** (founder, 2026-10-12). Moderators lead ordinary-member compromise cases. Moderators and the inviter receive the alert, the council is informed, and the Fool and council may follow up without being required for routine handling. Earlier invitation references support escalation when the immediate inviter is unavailable. Council leads professional compromise cases. Notification visibility is distinct from case-handling authority and does not grant access to private conversations. |
| D65 | **Separate handles from cards; ordered succession and authorised council-card rotation** (founder, 2026-10-12). The Fool may be `@laniina`, display name `La niina`, card `The Fool`: handles are personal and unique within Tero, not leadership titles. This corrects D63's `@thefool` assumption. Acting Sequence 0 retains their own card, handle, and invitation tree. The Fool sets the successor order. On the Fool's return, the first two successors are informed; restoration requires at least three council approvals plus the existing 24-hour wait. The Fool card is never reassigned. Council cards can return to rotation after authorised revocation, superseding D60's lifetime prohibition for council cards. The Fool may revoke council cards directly; council revocation requires a democratic vote during a live council audio call with all council members alerted, subject to the previously specified veto. Exact voting thresholds and target eligibility remain unresolved. |
| D66 | **Professional credentials are available by application to any admitted member** (founder, 2026-10-12). A member selects a supported professional category, supplies one-time category-appropriate verification evidence, and is reviewed by council. Approval is by council vote or direct Fool approval; direct approval ends the pending vote without requiring its completion. Approval grants a distinct verified category badge, corresponding listing, and professional activity within that scope, without changing the member's identity, invitation branch, or governance powers. This extends D12 and replaces the earlier special-professional-invitation/Sequence requirement. Category definitions, vote thresholds, organisation representation, and credential lifecycle remain to be specified and built. |
| D67 | **24-hour council revocation voting with immediate target restrictions** (founder, 2026-10-12). Unanimity is not required: the side with the higher vote ratio wins within a 24-hour voting window. Opening a valid revocation case immediately makes the targeted councillor predominantly read-only until resolution, allowing only council-call listening/speaking and comments within council discussions as write exceptions. Other actions and comments are blocked. A pending case does not itself release the card. Vote denominator, minimum participation, ties, proposal authority, and restoration/cancellation rules remain unresolved. This refines D65's voting rule without replacing the separate three-approval requirement for restoring the Fool. |
| D68 | **Direct moderator appointments and private leadership badges** (founder, 2026-10-12). The Fool or a council member may appoint a moderator without a vote. Moderators receive badges; Fool and council members also have badges, visible only to the Fool and council. Badge presentation does not establish permissions. The audience for professional and moderator badges is awaiting clarification; these badges and visibility controls remain unbuilt. |
| D69 | **Confirmed badge audiences and revocation vote outcomes** (founder, 2026-10-12). Members can see professional and moderator badges; only the Fool and council can see leadership badges. This resolves D68's audience question. In a council revocation vote, more revoke votes than retain votes means revocation wins, subject to the existing Fool veto. A tie or no votes means no revocation and the restrictions from that case are lifted at closure. Minimum participation and remaining finalisation rules are not yet specified. This resolves D67's vote comparison and tie/no-vote questions without changing the 24-hour window. |
